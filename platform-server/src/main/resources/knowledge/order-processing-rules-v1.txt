万众享订单处理规则说明
文档编号：wx_order_rules
版本：v1-20261002
整理日期：2026-10-02
资料性质：根据项目当前 Java 源码整理的实现说明，用于学习检索；不代表已经审批发布的运营制度。

一、订单状态与支付状态
订单状态分别为：1 待付款、2 待接单、3 已接单、4 派送中、5 已完成、6 已取消。
支付状态分别为：0 未支付、1 已支付、2 退款。
订单状态和支付状态是两个不同字段。订单状态 2 表示待接单，支付状态 2 表示退款，不能混为一谈。
来源：Orders.java 中订单状态与支付状态常量。

二、用户取消订单
在当前定义的六种订单状态范围内，用户可以取消待付款或待接单的订单。已接单、派送中、已完成、已取消的订单会因状态不符合要求而被拒绝取消。
取消前先检查订单是否存在；不存在则抛出订单不存在异常。
取消成功时，订单状态修改为已取消，取消原因记录为“用户取消”，并记录取消时间。
待接单订单被用户取消时，当前代码还会将支付状态设为退款。但外部支付退款调用被注释，不能据此声称支付渠道已经实际退回资金。
来源：OrderServiceImpl.userCancelById。

三、管理端拒单
管理端拒单要求订单存在，并且订单状态为待接单。订单不存在或者状态不为待接单时，抛出订单状态错误异常。
拒单成功时，订单状态修改为已取消，同时保存拒单原因和取消时间。
当前实现对已支付订单记录“申请退款”日志，但外部支付退款调用被注释；日志不代表真实退款完成。
来源：OrderServiceImpl.rejection。

四、开始派送
开始派送要求订单存在，并且订单状态为已接单。待付款、待接单、派送中、已完成、已取消的订单不符合该方法的派送前提。
校验通过后，订单状态从已接单修改为派送中。
订单不存在或者状态不符合要求时，抛出订单状态错误异常。
来源：OrderServiceImpl.delivery。

五、完成订单
完成订单要求订单存在，并且订单状态为派送中。已接单的订单不能直接通过该方法标记为已完成。
校验通过后，订单状态从派送中修改为已完成，同时记录实际送达时间。
订单不存在或者状态不符合要求时，抛出订单状态错误异常。
来源：OrderServiceImpl.complete。

六、本资料的范围
本资料仅解释以上状态和方法的当前实现，不提供订单实时数据，不包含昨日营业额、当前订单笔数、优惠券政策、商户结算周期或退款到账时限。
某一笔订单当前处于什么状态，需要另行查询业务数据库，不能从本规则文档推断。
