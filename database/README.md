# 数据库初始化

使用 MySQL 8，在**新建空数据库**中按以下顺序执行，不要在现有业务库直接运行：

1. `01-business-schema.sql`：11 张业务表，仅保留结构。
2. `02-ai-schema.sql`：4 张 AI 会话、消息与规则目录表，已经包含 `turn_id`。
3. `03-demo-data.sql`：合成的演示管理员、分类、商品与组合商品。
4. `04-rule-catalog.sql`：登记随仓库提供的 4 份规则快照，初始为 `PENDING`、无生效版本。

脚本不包含原数据库的用户、地址、订单、聊天记录或账号数据。演示账号是 `admin / Demo123456!`，只用于本地体验；订单初始为空，经营查询会返回无订单，不能将它当作已有真实营业额。

规则目录登记后仍需登录并调用导入接口，实际完成 Embedding 与 Milvus 写入，才能发布生效版本。不要手工把目录提前改成 `READY`。导入步骤见根目录 [README](../README.md)。

旧库迁移应按实际字段做增量变更；这里提供的是新安装流程，不会替你自动迁移或清理旧数据。
